## 다음 작업 순서

1. **F4 실제 조작 확인:** Pleos AVD에서 재생 중 일시정지 → 재개(현재 항목 처음부터) → 다음 주제(완료로 기록되지 않음)를 확인한다. 실제 음성 출력 자체는 사용자가 이미 확인했다.
2. **F4/F7 통합:** PR #8과 #9를 제품 기준에서 함께 빌드하고, 완주 항목만 오늘의 발견에 나타나는지 테스트한다. 검증 전 PR을 병합 완료로 간주하지 않는다.
3. **도착 후 결과:** 이슈 #6에 따라 로컬 문항·선택·채점·결과를 구현하고 Fake 도착으로 시작 조건을 검증한다. 주차(P)와 도착 상태를 분리한다.
4. **ETA·주행·지역:** F2 단위는 공식 문서나 SDK 근거가 확인될 때만 변환한다. 그 전까지는 테스트 ETA 15분을 유지한다. 남은 시간에 따라 F6 주행 제한과 F5 지역 진입을 우선순위에 맞춰 추가한다.
5. **제출 리허설:** 기본 브랜치 기준 APK를 만들고 ETA → 브리핑 구성 → TTS → 도착 후 오늘의 발견/퀴즈 흐름을 AVD에서 리허설한 뒤 영상을 만든다.

## 개발 환경 재개

현재 F4 작업 트리는 `/Users/tokkislove/AndroidStudioProjects/Routeonomy-f2`, 브랜치는 `feat/f4-tts-2`이다. 실험용 `/Users/tokkislove/AndroidStudioProjects/Routeonomy`와 혼동하지 않는다.

노트북을 쉬게 할 때:

1. 열려 있는 파일을 저장하고 Gradle 빌드/동기화가 끝났는지 확인한다.
2. 메모리를 아끼려면 Android Studio를 종료하기 전에 Pleos AVD 창을 닫거나 Device Manager에서 해당 기기의 Stop을 누른다. **Wipe Data, Cold Boot, 삭제는 누르지 않는다.**
3. Android Studio 메뉴에서 **Android Studio > Quit Android Studio**를 누르거나 `⌘Q`를 누른다. 프로젝트 파일과 Git 브랜치는 그대로 보존된다.

다시 시작할 때:

1. Android Studio를 열고 **Open** 또는 **File > Open...**을 선택한다.
2. `/Users/tokkislove/AndroidStudioProjects/Routeonomy-f2`를 연다. 실험 프로젝트인 `Routeonomy`는 열지 않는다.
3. 프로젝트 동기화가 끝나면 브랜치가 `feat/f4-tts-2`인지 확인한다.
4. AVD 확인이 필요한 날에는 **Tools > Device Manager**에서 `Pleos_Connect_v2.1.0` 행의 ▶를 누르고 부팅을 기다린다.
5. 상단 실행 구성에서 `app`, 기기에서 `Pleos Connect v2.1.0`을 선택하고 초록색 ▶ **Run**을 누른다. AVD가 필요 없는 코드 작업은 기기를 켜지 않아도 된다.
